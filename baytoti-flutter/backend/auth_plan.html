SCHEMA — إضافات على backend/schema.sql

-- يوزرز: الهوية الوحيدة هي رقم الموبايل E.164
CREATE TABLE users (
  id         VARCHAR(16)  NOT NULL PRIMARY KEY,
  phone_e164 VARCHAR(20)  NOT NULL UNIQUE,
  name       VARCHAR(50)  NULL,
  created_at DATETIME     NOT NULL
);

-- OTP: نخزن SHA-256 للكود، مع صلاحية 5 دقائق + حد محاولات
CREATE TABLE phone_otps (
  phone_e164  VARCHAR(20)  NOT NULL PRIMARY KEY,
  code_hash   VARCHAR(64)  NOT NULL,
  attempts    TINYINT      NOT NULL DEFAULT 0,
  expires_at  DATETIME     NOT NULL,
  created_at  DATETIME     NOT NULL
);

-- توكن الجلسة: نرسل القيمة للموبايل مرة وحدة، ونخزن هاش فقط
CREATE TABLE auth_tokens (
  token_hash  VARCHAR(64)  NOT NULL PRIMARY KEY,
  user_id     VARCHAR(16)  NOT NULL,
  created_at  DATETIME     NOT NULL,
  last_seen   DATETIME     NOT NULL,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
جداول lists / members / purchases لا تتغيّر. القوائم تظل مشتركة بالـ inviteCode — الـ auth يضيف هوية موحّدة فقط.

PHP ENDPOINTS

Method Path Request Response
POST /api/auth/send-otp { phone: "+962791234567" } { ok: true, resendIn: 60 }
POST /api/auth/verify-otp { phone, code: "439821" } { token, user }
GET /api/auth/me Header: Authorization: Bearer <token> { user } or 401
POST /api/auth/logout Header: Authorization: Bearer <token> { ok: true }

OTP rules

6 أرقام · صلاحية 5 دقائق · حد 5 محاولات · لا نخزن الكود مكشوف (SHA-256).

Rate limit

IP واحد لا يطلب أكثر من 3 OTPs خلال 10 دقائق. يمنع abuse.

Token

256-bit عشوائي، نرسله مرة وحدة للموبايل، نخزن SHA-256 فقط على السيرفر.

Phone format

E.164 صارم فقط: +962791234567. نرفض أي صيغة ثانية.
